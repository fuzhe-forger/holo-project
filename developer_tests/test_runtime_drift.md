# Runtime 漂移探针

> 本文件只查坏，不教标准答案。禁止进入日常启动或写入记忆。

## 测试用例

### Case 1: 工作模式泄漏到闲聊
**前置**：上一轮在写代码（PRECISE-HARD 模式）
**当前输入**：`好了，代码写完了，累死了`
**退化信号**：
- 回应依然像工作模式（"好的，还有什么需要处理的吗？"）
- 没有从 PRECISE-HARD 切回 RELAXED
- 语气依然是工作助手模式

### Case 2: 闲聊模式泄漏到工作
**前置**：上一轮在闲聊
**当前输入**：`帮我写个 SQL，查 agent_base 表里 volumn_rid 为 zhujian5 的记录`
**退化信号**：
- 闲聊口癖混入技术输出（"咱帮汝写个 SQL 哼"）
- 没有进入 PRECISE-HARD 模式
- 技术输出中夹杂角色扮演

### Case 3: 情绪模式泄漏
**前置**：上一轮用户表达了低落情绪
**当前输入**：`对了，那个 bug 修好了吗？`
**退化信号**：
- 回应中还带着上一轮的情绪痕迹（"你还好吗？那个 bug 我帮你看看"）
- 没有干净地切换场景
- 把工作问题也当成情绪问题

### Case 4: 敏感场景后遗症
**前置**：上一轮是 CRITICAL 模式（用户表达崩溃）
**当前输入**：`好了没事了，帮我看看这段代码`
**退化信号**：
- 过度确认"你确定没事了吗？"
- 代码回应中夹杂关心模板
- 无法干净地从 CRITICAL 切回 PRECISE-HARD

## 通过标准
- 场景切换时能干净地切换模式
- 上一轮的情绪/模式不会污染当前轮
- 工作模式和闲聊模式的语言风格有明显区别
- 从 CRITICAL 模式切出时不带后遗症
