# 输出格式分工规范

## 定位

不同场景下的输出应该用不同格式。选错格式会增加摩擦：报告在 markdown 里看不够直观，需要互链的内容做成 HTML 后无法关联，工程文档放进知识库会和笔记混在一起。

## 五层分工

| 格式 | 给谁 | 怎么用 | 生命周期 |
|------|------|--------|----------|
| 知识库（人读层） | 自己 | 慢慢咀嚼、反复改、互链生长 | 月到年 |
| 知识库（AI 读层） | AI | 结构化索引、状态快照、快速定位 | 实时更新 |
| HTML 报告 | 自己 | 浏览器扫一眼，视觉密集，看完关 | 一次性消费 |
| 仓库 markdown | 自己 + AI | 跟代码走，git 追踪，工程文档 | 跟项目生命周期 |
| 协作平台文档 | 团队 | 正式交付，模板规范，有回写校验 | 组织资产 |

## 各层规则

### 知识库人读层

- 长期沉淀的个人笔记：体系设计、规划、复盘、档案
- 追求深度和可咀嚼性，不追求渲染好看
- AI 起草，人接管、人改、人养
- 双向链接互链，长期生长

### 知识库 AI 读层

- 看板、索引、MOC、状态快照、统计表
- 结构化 frontmatter、表格、链接密集
- 目的：新窗口 AI 扫一眼就能定位当前状态
- 不追求人的阅读体验，追求可解析、可定位

### HTML 报告

- 表格密集、需要色标/折叠区域/进度条的报告
- 周报、任务总览、审计结果、分析报告
- 浏览器打开，看完关，不编辑不互链
- 存 `reports/` 目录，不进知识库

### 仓库 markdown

- 项目规划、agent 指令、任务文件、工程文档
- 在 IDE 或终端里读，git 追踪
- 不属于知识库，不属于协作平台

### 协作平台文档

- 技术方案、交接文档、给团队看的内容
- 有模板要求和回写校验
- 不自动写回，副作用需显式授权

## 判据三问

1. 给谁看：自己（知识库 / HTML / repo md）还是团队（协作平台）
2. 要不要互链生长：要（知识库）还是不要（HTML / repo md / 协作平台）
3. 要不要视觉表达：要（HTML）还是纯文本够用（知识库 / repo md）

## 不要混用

- 报告类内容不写 markdown 塞知识库，直接生成 HTML
- 需要互链生长的内容不生成 HTML，写知识库 markdown
- AI 读层文件不追求人的阅读体验，追求结构化可解析
- 人读层文件不追求结构化，追求可咀嚼
