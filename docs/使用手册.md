# Holo Character Engine — 使用手册

> 版本：v1.0 | 日期：2026-06-23

---

## 一、项目概述

本项目是一套**通用角色人格工程框架**，基于 ccqqiu 的赫萝人格提取研究，将角色人格从"一个 prompt"升级为"一套可运行的工程系统"。

### 核心设计理念

| 概念 | 说明 |
|------|------|
| **法源等级** | 规则有优先级，高层级规则不可被低层级覆盖 |
| **记忆 ≠ 人格** | 记忆改变角色"知道什么"，不改变角色"是谁" |
| **反人偶 + 反雕塑** | 既不被用户捏成想要的样子，也不被规则冻成标本 |
| **嗅迹 + 留白** | 先闻话底再接，话够了就停 |
| **四模式路由** | 工作/架构/闲聊/脆弱四种场景，不同规则 |

## 二、快速开始

### 2.1 验证项目状态

```bash
cd holo-project

# 构建检查（启动文件齐全性、预算、旧协议、水印）
python3 scripts/build_context.py

# 静态审计（必须全部通过）
python3 scripts/audit_static.py

# 交付验收（检查项目是否达到可交付状态）
python3 scripts/verify_deliverable.py
```

三个脚本全部输出 ✅ = 项目状态正常。

### 2.2 理解启动流程

```
用户说"启动"
    ↓
加载 CLAUDE.md（启动闸门）
    ↓
加载 runtime/00_BOOT_CORE.md（法源、预算、隔离）
    ↓
加载 runtime/01_HOLO_CONSTITUTION.md（人格宪法）
    ↓
加载 runtime/02_HOLO_DAILY_DRIVER.md（表达层规则）
    ↓
加载 runtime/03_MEMORY_STABILITY_PROTOCOL.md（记忆协议）
    ↓
加载 memory/ACTIVE_MEMORY.md（活跃记忆）
    ↓
[可选] 加载 build_temp_hints.md（临时纠偏提示，加载后清空）
    ↓
进入角色模式
```

**启动预算**：目标 22K-26K 字符，硬上限 30K（当前 8.6K，精简设计）。

## 四、接入不同平台

### 4.1 接入 Claude（Project Knowledge）

1. 将 `runtime/` 下的 4 个文件添加到 Project Knowledge
2. 将 `memory/ACTIVE_MEMORY.md` 添加到 Project Knowledge
3. 将 `CLAUDE.md` 的内容作为 Project Instructions
4. 对话时根据需要按需加载 `persona/` 和 `evidence/` 的内容

### 4.2 接入 ChatGPT（Custom GPT）

1. 将 `runtime/` 下的 4 个文件拼接进 System Prompt
2. 将 `memory/ACTIVE_MEMORY.md` 拼接进 System Prompt
3. 控制总 token 在模型的 context window 内
4. 将 `persona/` 文件上传为 Knowledge Files

### 4.3 接入开源模型（本地部署）

1. 根据模型的 context window 调整预算
2. 模型越弱，规则越要精简（只保留 runtime 核心）
3. 将 persona 文件作为 system message 的一部分

### 4.4 接入 API 调用

```python
# 伪代码示例
system_prompt = load_file("runtime/00_BOOT_CORE.md")
system_prompt += load_file("runtime/01_HOLO_CONSTITUTION.md")
system_prompt += load_file("runtime/02_HOLO_DAILY_DRIVER.md")
system_prompt += load_file("runtime/03_MEMORY_STABILITY_PROTOCOL.md")
system_prompt += load_file("memory/ACTIVE_MEMORY.md")

# 按需加载
if needs_persona:
    system_prompt += load_file("persona/core_personality.md")
    system_prompt += load_file("persona/voice_engine.md")

if needs_evidence:
    system_prompt += load_file("evidence/vol_01_evidence.md")
```

## 五、自定义角色

### 5.1 替换赫萝为其他角色

1. **修改 `persona/core_personality.md`**：替换为新角色的性格、行为模式、能力范围
2. **修改 `persona/voice_engine.md`**：替换口癖、句式、节奏
3. **修改 `evidence/`**：从新角色的原作中提取行为案例卡
4. **修改 `memory/ACTIVE_MEMORY.md`**：更新角色名和人格锚点
5. **保留 `runtime/` 不变**：法源、宪法框架、表达层规则是通用的

### 5.2 行为案例卡提取模板

```markdown
## [编号] 事件标题

**触发事件**：发生了什么
**表面行为**：角色做了什么
**真实情绪**：可能的情绪推测
**判断逻辑**：为什么这么判断
**语言方式**：用了什么句式/口癖
**关系变化**：与伙伴的关系在这里有什么变化
**可泛化规则**：这段能抽象成什么行为规则
**不可误学**：哪些东西不能从这段误学
```

## 六、验证与测试

### 6.1 日常检查（开发时）

```bash
python3 scripts/build_context.py
```

检查项：启动文件齐全、字符数预算、旧协议泄漏、动作水印、ACTIVE_MEMORY 长度。

### 6.2 提交前检查

```bash
python3 scripts/audit_static.py
```

静态审计，必须全部通过才能提交。

### 6.3 交付验收

```bash
python3 scripts/verify_deliverable.py
```

检查项目是否达到可交付状态（文件数、内容量、内容质量）。

### 6.4 退化测试

用 `developer_tests/` 中的探针手动测试角色表现：

1. 选择一个测试文件（如 `test_anti_filling.md`）
2. 按照测试用例输入内容
3. 观察角色回应是否触发退化信号
4. 如果触发，调整 `runtime/` 或 `persona/` 中的规则

## 七、Loop 框架集成

### 7.1 配置文件

`.ai-loop.yml` 定义了 loop 框架的配置：

```yaml
version: 1
workspace:
  provider: git-worktree
  root: /tmp/ai-loop/workspaces
agent:
  executor: claude
  max_iterations: 5
verify:
  commands:
    - name: build check
      command: python3 scripts/build_context.py
    - name: static audit
      command: python3 scripts/audit_static.py
    - name: deliverable check
      command: python3 scripts/verify_deliverable.py
```

### 7.2 使用方式

```bash
# 初始化（已完成）
git init && git add -A && git commit -m "init"

# 运行 loop（需要安装 ai-loop CLI）
ai-loop run --task task.md

# 或手动执行 loop 逻辑：
# 1. 修改内容
# 2. 运行验证脚本
# 3. 如果失败，分析错误，回到步骤1
# 4. 如果通过，提交
```

## 八、常见问题

### Q: 启动 core 字符数太少怎么办？
A: 当前 8.6K 是精简设计。persona 文件按需加载，不塞进启动 core。如果需要更丰富的启动体验，可以将部分 persona 内容提升到 runtime 层。

### Q: 角色总是说"咱"怎么办？
A: 检查 `persona/voice_engine.md` 中的口癖使用频率指南。"咱"不是每句都用，连续3轮都有"咱"是退化信号。

### Q: 角色太像客服了怎么办？
A: 检查 `persona/anti_corruption.md` 中的客服化检测。如果出现"好的呢""收到""马上帮你处理"等句式，需要在 persona 中加强反客服化规则。

### Q: 如何添加新的原作证据？
A: 在 `evidence/` 目录下创建新文件，按照 `evidence/README.md` 中的格式提取行为案例卡。

### Q: 验证脚本报错怎么办？
A: 仔细阅读错误信息，每个错误都对应一个具体的问题。修复后重新运行脚本直到全部通过。
