# Holo Character Engine — 项目报告

> 版本：v1.0 | 日期：2026-06-23

---

## 一、项目背景

本项目基于 ccqqiu 在知乎发布的《关于"赫萝"的虚拟角色人格提取心得》，将其中描述的角色人格工程方法论落地为一套可运行的工程框架。

原文描述了从 v4 到 v9.7.3 的迭代过程，核心创新包括：
- **法源等级系统**：解决规则冲突时的裁决问题
- **人格宪法**：区分"记忆"和"人格"，防止记忆反向污染人格
- **反人偶 + 反雕塑**：在"用户谄媚"和"规则僵化"之间找到窄路
- **嗅迹 + 留白**：解决大模型的"完整性焦虑"问题
- **四模式路由**：解决跨场景人格污染问题

本项目将上述方法论转化为标准化的文件结构和工程脚本，使其可以被复用于任意角色。

## 二、技术架构

### 2.1 分层架构

```
┌─────────────────────────────────────┐
│         CLAUDE.md（启动闸门）          │  ← 用户交互层
├─────────────────────────────────────┤
│    runtime/（法源 + 宪法 + 表达层）     │  ← 运行核心层（每次启动必读）
├─────────────────────────────────────┤
│    memory/（六态记忆系统）              │  ← 记忆层（ACTIVE必读，其他按需）
├─────────────────────────────────────┤
│    persona/（9个人格引擎）              │  ← 人格层（按需加载）
├─────────────────────────────────────┤
│    evidence/（原作行为案例卡）           │  ← 证据层（按需回灌）
├─────────────────────────────────────┤
│    context_packs/（场景包）             │  ← 场景层（匹配时加载）
├─────────────────────────────────────┤
│    developer_tests/（退化探针）         │  ← 测试层（外置，不进启动）
├─────────────────────────────────────┤
│    scripts/（构建/审计/验收）           │  ← 工程保障层
└─────────────────────────────────────┘
```

### 2.2 法源等级（规则优先级）

```
1. 安全与现实边界          ← 绝对不可覆盖
2. 人格宪法                ← 角色核心，不可被前台修改
3. 工作可靠性              ← 技术准确性
4. 当前任务上下文          ← 具体需求
5. 日常驾驶规则            ← 表达层
6. 记忆系统                ← 知道什么
7. 原作证据                ← 行为依据
8. 参考材料                ← 能看但不自动污染
9. 旧版本材料              ← 仅追溯
```

### 2.3 四模式路由

| 模式 | 触发条件 | RP程度 | 口癖 |
|------|---------|--------|------|
| PRECISE-HARD | 代码/SQL/bug/部署 | 零 | 无 |
| PRECISE-ARCH | 人格工程/架构讨论 | 低 | 极少 |
| RELAXED | 日常闲聊 | 正常 | 正常 |
| CRITICAL | 崩溃/自伤/极端情绪 | 低 | 无 |

## 六、开发过程

### 6.1 迭代轨迹

| Round | 修复项 | 结果 |
|---|---|---|
| 1 | evidence + runtime 缺口 | 4个错误 → 3个 |
| 2 | persona 增长协议 + 原作融合 | 3个 → 2个 |
| 3 | evidence + memory 扩展 | 2个 → 1个 |
| 4 | context_packs + memory 展开 | 1个 |
| 5 | persona 大幅扩展 | 1个 |
| 6 | evidence + developer_tests | 1个 |
| 7 | voice_engine + context_packs | 1个 |
| 8 | 最终收尾 | ✅ 全部通过 |

### 6.2 关键决策

1. **启动 core 精简设计**：只保留 runtime + ACTIVE_MEMORY，persona 按需加载，减少 token 浪费
2. **法源等级系统**：借鉴法律系统的优先级概念，解决规则冲突
3. **反人偶+反雕塑双向防御**：同时防止被用户捏和被规则冻
4. **嗅迹-留白表达**：解决大模型的"完整性焦虑"
5. **六态记忆+PENDING审核**：防止记忆反向污染人格
