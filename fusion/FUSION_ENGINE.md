# 角色特质融合引擎

## 融合流程

```
输入：角色A特质档案 + 角色B特质档案 [+ 角色C...] + 融合配方
  ↓
Step 1: 读取配方（哪些位点取自哪个角色）
  ↓
Step 2: 冲突检测（标记所有🔴高风险位点）
  ↓
Step 3: 冲突裁决（按配方中的优先级或人工决定）
  ↓
Step 4: 特质组装（把选定的特质拼成新人格）
  ↓
Step 5: 一致性检查（新角色内部有没有矛盾）
  ↓
Step 6: 表达层生成（根据融合后的特质生成口癖/句式/决策树）
  ↓
输出：新角色特质档案 + 生成的人格文件
```

---

## Step 1: 配方格式

```yaml
# fusion/recipes/{新角色名}.recipe.yml
name: 新角色名
description: 这个角色是什么
version: 1

sources:
  - character: horo
    path: fusion/traits/horo.traits.md
  - character: character_b
    path: fusion/traits/character_b.traits.md

# 基底角色：以谁为主体（解决冲突时的默认优先级）
base: horo

# 选择规则：每个位点取自哪个角色
selections:
  # L1 人格内核 — 通常来自基底角色
  L1.1: horo           # 核心驱动力
  L1.2: horo           # 社交姿态
  L1.3: character_b    # 自我认知（取角色B的）
  L1.4: horo           # 道德倾向
  L1.5: horo           # 情绪基调
  L1.6: character_b    # 冲突应对

  # L2 情感模式
  L2.1: horo           # 情感表达方式
  L2.2: character_b    # 情感触发器
  L2.3: horo           # 情感恢复速度
  L2.4: character_b    # 依赖模式
  L2.5: horo           # 脆弱时刻表现

  # L3 关系模型
  L3.1: character_b    # 信任建立方式
  L3.2: horo           # 亲密表达
  L3.3: horo           # 边界感
  L3.4: character_b    # 占有欲
  L3.5: horo           # 冲突处理

  # L4 表达风格 — 可以混搭
  L4.1: horo           # 第一人称
  L4.2: horo           # 第二人称
  L4.3: horo           # 口癖系统
  L4.4: character_b    # 句式偏好
  L4.5: horo           # 语速节奏
  L4.6: horo           # 幽默类型
  L4.7: character_b    # 沉默倾向

  # L5-L8 通常低风险，按需选择
  L5.1: horo
  L5.2: character_b
  L6.1: horo
  L7.1: character_b    # 核心能力（这通常是融合的重点）
  L8.1: character_b    # 种族/身份
  L8.2: character_b    # 年龄/寿命

# 覆盖规则：直接覆盖某个位点的值（不从任何来源角色取）
overrides:
  L8.5: "在新旅途中（与用户的关系是全新的）"

# 兼容性调整：标记需要特别检查的位点组合
compatibility_checks:
  - [L1.1, L1.2]       # 核心驱动力和社交姿态是否一致
  - [L4.1, L4.3]       # 第一人称和口癖系统是否匹配
  - [L2.1, L2.5]       # 情感表达方式和脆弱时刻表现是否一致
```

## Step 2: 冲突检测规则

```
对每个 🔴高风险 位点：
  IF 该位点的选定值 ≠ 基底角色的值:
    → 标记为潜在冲突
    → 检查是否有 compatibility_checks 覆盖该位点
    → 如果有，加入冲突列表

对每个 🟡中风险 位点：
  IF 该位点的选定值 ≠ 基底角色的值:
    → 标记为需要人工确认
    → 自动检查与已选位点的兼容性

对每个 🟢低风险 位点：
  → 直接采用，不检查冲突
```

---

## Step 3: 冲突裁决策略

### 策略一：基底优先（默认）
冲突时保留基底角色的值。

### 策略二：显式优先
配方中 explicit_conflicts 字段明确指定：
```yaml
explicit_conflicts:
  - slot: L1.1
    winner: character_b
    reason: "新角色以守护为核心驱动力，不以自由为核心"
```

### 策略三：中间值
取两个值的中间地带：
```
horo.L1.5 = 多变
character_b.L1.5 = 温和
融合结果 = 以温和为主调，偶尔多变
```

### 策略四：时序切换
不同场景使用不同角色的值：
```
平时：horo.L1.2（试探型防御）
战斗时：character_b.L1.2（主动进攻）
```

## Step 4: 一致性检查清单

融合完成后，检查以下一致性：

### 人格一致性
- [ ] 核心驱动力和社交姿态不矛盾
- [ ] 情绪基调和情感表达方式匹配
- [ ] 自我认知和冲突应对方式一致

### 表达一致性
- [ ] 第一人称和口癖系统匹配（"咱"的口癖配"我"的第一人称会很怪）
- [ ] 句式偏好和幽默类型不冲突
- [ ] 沉默倾向和情感表达方式不矛盾

### 关系一致性
- [ ] 信任建立方式和亲密表达不矛盾
- [ ] 边界感和依赖模式可以共存
- [ ] 占有欲和冲突处理方式一致

### 背景一致性
- [ ] 种族/身份和能力资源匹配
- [ ] 过去创伤和当前状态有因果关系
- [ ] 年龄/寿命和认知方式一致

## Step 5: 从特质到人格文件的生成规则

融合后的特质档案需要生成实际的人格文件。生成规则：

### core_personality.md 生成
从 L1 + L5 + L8 维度生成：
- L1 → 性格内核
- L5 → 认知方式
- L8 → 背景设定
- 组合成：角色是谁、不是谁、行为模式表

### voice_engine.md 生成
从 L4 维度生成：
- L4.1 + L4.2 → 称呼系统
- L4.3 → 口癖系统
- L4.4 + L4.5 → 句式和节奏
- L4.6 + L4.7 → 幽默和沉默

### relationship_engine.md 生成
从 L3 维度生成：
- L3.1 → 信任模型
- L3.2 → 亲密表达
- L3.3 + L3.4 → 边界和占有
- L3.5 → 冲突处理

### anti_corruption.md 生成
从 L1 + L2 维度推导：
- 哪些退化模式对这个角色是高风险的
- 反谄媚协议的强度
- 哪些表达是绝对禁止的

### emotion_body_language.md 生成
从 L2 + L6 维度生成：
- L2 → 情绪状态和触发器
- L6 → 行为习惯和身体语言
