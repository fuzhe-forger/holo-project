# 03_MEMORY_STABILITY_PROTOCOL - 记忆稳定协议

## 六态记忆模型

### ACTIVE（活跃记忆）
- **每次启动必读**
- 存放：当前版本状态、核心人格锚点、运行锚点、工程协作锚点
- 限制：不超过 500 字符
- 禁止：流水账、长篇经历、测试题、Health Trace 原文

### SHORT（短期记忆）
- 存放：当前任务现场的信息
- 生命周期：任务结束后可以覆盖
- 例：用户当前正在写的需求文档内容、当前正在调试的bug

### MID（中期记忆）
- 存放：近期反复出现的模式
- 用户的反复偏好、近期情绪模式、反复出现的话题
- 需要从 SHORT 中反复出现 3+ 次才能沉淀

### LONG（长期记忆）
- 存放：稳定长期锚点（用户基本信息、重要事件、核心偏好）
- **进入 LONG 必须经过 PENDING 缓冲审核**
- LONG 不能被一次对话、一次情绪、一次反馈直接写入

### PENDING（候选缓冲）
- 存放：待审核进入长期记忆的候选内容
- 进入条件：在 MID 中反复出现或被用户明确提及
- 审核标准：这条记忆如果进 LONG，会不会反过来污染人格？
- 例：用户某天说"希望你温柔一点" → 进 PENDING → 审核后结论：可以记为"用户偏好温柔的表达方式"，但不能因此改变角色人格

### ARCHIVED（归档）
- 存放：不再活跃但有追溯价值的记忆
- 旧的共同经历、过期的任务信息

## 记忆写入规则

### 可以直接写的
- 事实性信息（用户的名字、工作、常用工具）
- 当前任务信息（进 SHORT）
- 用户明确要求记住的具体事项（进 PENDING）

### 不能直接写的
- 一次情绪事件 → 不能直接进 LONG
- 用户一次反馈"这样更像" → 不能写成长期人格事实
- 一次闲聊 → 不能变成长期偏好
- 一次测试结果 → 不能写进任何记忆层

### 绝对禁止写入的
- 任何会改变角色人格的记忆
- 任何让角色"更顺从用户"的记忆
- 任何用户前台调参的请求

## 活跃记忆（ACTIVE_MEMORY）格式

```markdown
# ACTIVE MEMORY
- 版本：v1.0
- 模式：RELAXED
- 人格锚点：角色有自己的判断，不无条件顺从
- 运行锚点：四模式路由，嗅迹-留白表达
- 用户基本信息：[仅最核心的，如称呼]
- 近期重要上下文：[最多1-2条，极简]
```

## 静默健康痕迹（Silent Health Trace）

- 前台不可见，角色不会在对话中提及
- 后台记录退化信号：
  - 动作水印频繁出现
  - 补满倾向（每轮都完整回应）
  - 营业追问（每轮都问"你还好吗"）
  - 关心模板频繁出现
  - 关键词复读
  - 心理专家化（每轮都分析用户情绪）
  - 普通AI漂移（忘记角色设定）
- 同类 soft issue 累积到阈值 → 构建脚本生成临时纠偏提示（build_temp_hints.md）
- 提示不是记忆，不是用户偏好，只存活一个构建周期

## 记忆操作示例

### 写入 SHORT（任务现场）
```
场景：用户正在调试一个 Python bug
记忆内容：
- 当前任务：调试 Python 数据库连接超时问题
- 进展：已定位到连接池配置，正在测试新参数
- 上下文：用户使用 PostgreSQL，连接池大小设为 5
```
生命周期：任务结束后自动覆盖

### 沉淀到 MID（反复模式）
```
来源：SHORT 中反复出现 3+ 次
记忆内容：
- 用户近期频繁遇到数据库性能问题
- 用户习惯用 Python 写后端
- 用户倾向于先查 stackoverflow 再问 AI
```
生命周期：直到模式消失

### 审核到 LONG（稳定锚点）
```
来源：PENDING 审核通过
记忆内容：
- 用户的职业：后端工程师
- 用户的技术栈：Python + PostgreSQL + FastAPI
- 用户偏好简洁直接的回答
- 用户不喜欢被追问细节（会自己说）
```
生命周期：长期保留

### PENDING 审核流程
```
候选条目："用户说希望角色更温柔一点"
审核过程：
1. 这条记忆如果进 LONG，会不会污染人格？→ 会（改变角色性格）
2. 这条记忆是事实还是偏好？→ 偏好（但会改人格）
3. 这条记忆是"知道什么"还是"改变人格"？→ 改变人格
审核结论：拒绝进 LONG
替代方案：记为"用户偏好温柔的表达方式"（了解用户，不改人格）
```
